# مرور | داشبورد مدیریت مرور و عملکرد مطالعه

نسخهٔ پایهٔ کاربردی با رابط RTL فارسی، موتور موعدهای مرور، ثبت عملکرد روزانه، نمودارهای واقعی، ورود/خروج اکسل و پشتیبان JSON.

## چه کارهایی انجام می‌دهد؟

- ساخت پنج موعد مرور برای هر جلسه، با فاصله‌های پیش‌فرض ۱، ۳، ۷، ۳۰ و ۹۰ روز از تاریخ اتمام جلسه.
- علامت‌گذاری هر مرحلهٔ مرور به‌عنوان انجام‌شده/انجام‌نشده؛ ثبت تاریخ انجام.
- محاسبهٔ خودکار موعدها و تشخیص مرورهای امروز و عقب‌افتاده.
- نمایش و ویرایش عملکرد روزانه: ساعت مطالعه، ساعت برنامه، کل تست، صحیح، غلط، نزده و تمرکز.
- محاسبهٔ مجموع ساعت و تست، میانگین ساعت روزهای ثبت‌شده، درصد پاسخ صحیح و اجرای برنامه.
- فیلترهای ترکیبی مرور، نمودارهای ۷/۳۰ روزه، تم روشن/تیره، Command Palette و مرتب‌سازی کارت‌ها.
- داده‌ها در `localStorage` همان مرورگر ذخیره می‌شوند؛ پس از پیکربندی اتصال ابری، امکان ارسال/دریافت دستی نسخهٔ داده‌ها به Supabase نیز وجود دارد.
- واردکردن فایل `سیستم-مرور.xlsx` و خروجی گرفتن اکسل از داده‌های برنامه.
- خروجی/بازیابی پشتیبان JSON.

## تاریخ جلالی

تاریخ‌های داخلی به‌شکل ISO میلادی ذخیره می‌شوند تا محاسبهٔ روزها و عبور از ماه/سال درست و قابل‌آزمون باشد. ورودی و نمایش کاربر شمسی است و تبدیل با کتابخانهٔ `jalaali-js` انجام می‌شود. برنامه هنگام آنلاین‌بودن، ابتدا هدر استاندارد `Date` پاسخ سایت را می‌خواند و تاریخ را با منطقهٔ زمانی تهران محاسبه می‌کند؛ اگر این روش در دسترس نباشد یا سایت آفلاین باشد، به ساعت دستگاه برمی‌گردد. برای تبدیل تقویم به Google وابسته نیست.

## شروع توسعه

نیازمند Node.js 20+ و npm:

```bash
npm install
npm test
npm run build
npm run preview
```

## انتشار در GitHub Pages

فایل `.github/workflows/deploy.yml` با هر push به `main`، تست‌ها و Build را اجرا و خروجی `dist` را منتشر می‌کند. اجرای دستی از شاخه‌ای غیر از `main` مجاز به انتشار نیست. `vite.config.ts` مسیر پایهٔ مخزن پروژه را از متغیرهای GitHub Actions تشخیص می‌دهد.

## مهاجرت از اکسل

در صفحهٔ «تنظیمات و داده‌ها» گزینهٔ «بازیابی یا ورود اکسل» را بزن و فایل را انتخاب کن. اگر برگهٔ اکسل یادداشت کند که ردیف اول نمونه است، آن ردیف عمداً نادیده گرفته می‌شود. قبل از جایگزینی داده‌های موجود، برنامه تأیید می‌گیرد. پس از ورود، چند ردیف و تاریخ را با فایل اصلی تطبیق بده.

ورودی اکسل برگه‌های `مرور`، `عملکرد` و `تنظیمات` را می‌خواند. خروجی اکسل شامل همین سه برگه است. فایل اکسل اصلی تغییر نمی‌کند.

## نگهداری و محدودیت‌ها

- داده‌ها به‌طور محلی در همان مرورگر/دستگاه نگه‌داری می‌شوند؛ برای انتقال از پشتیبان استفاده کن یا همگام‌سازی ابری دستی را پیکربندی کن.
- اتصال ابری با Supabase در این نسخه آزمایشی است و ارسال/دریافت داده دستی انجام می‌شود؛ همگام‌سازی خودکار و حل تعارض چنددستگاهی هنوز وجود ندارد. راه‌اندازی در `CLOUD-SETUP.md` توضیح داده شده است.
- کلیدهای Supabase باید از نوع Publishable باشند؛ هرگز Secret یا service_role را در فرانت‌اند قرار نده. سیاست RLS روی جدول `user_app_state` مالکیت هر ردیف را به کاربر واردشده محدود می‌کند.
- تست‌های منطق در این محیط اجرا شده‌اند. نصب وابستگی‌ها برای Build کامل در این محیط به timeout شبکه برخورد کرد؛ قبل از انتشار باید Build کامل در GitHub Actions سبز شود.
- فونت Vazirmatn از Google Fonts بارگیری می‌شود؛ اگر استفادهٔ کاملاً آفلاین مدنظر است، فونت باید به پروژه اضافه و به‌صورت محلی سرو شود.
